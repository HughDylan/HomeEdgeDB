# HomeEdgeDB - 基于 FlashDB 的分布式智能家居边缘网关

##  项目简介
本项目基于 STM32F103C8T6 微控制器，构建了一个具备无线通信与本地存储能力的物联网边缘网关系统。系统分为发送端（节点）与接收端（主网关）。节点通过 nRF24L01 模块将温湿度数据隔空发送，主网关接收数据并利用 FlashDB 数据库进行持久化存储，实现掉电不丢。

## 核心踩坑记录：CRC 位数不一致导致静默丢包
在调试 nRF24L01 双机通信时，遇到了极其隐蔽的“假连通”问题：
- **现象**：发送端显示发送成功（或重发耗尽），但接收端死活收不到任何数据，串口无任何报错，属于“静默丢包”。
- **根因**：两块 nRF24L01 模块并非同一批次，出厂时的 `CONFIG` 寄存器默认值不同（特别是 **CRCO 校验位**，一个是 1 字节 CRC，一个是 2 字节 CRC）。校验方式不匹配，接收端底层直接丢弃了所有数据包。
- **解决方案**：摒弃直接给 `CONFIG` 写死数值的做法（如 0x0E / 0x0F）。改用**按位操作**，仅改变 `PWR_UP`（上电）和 `PRIM_RX`（收发模式）位，将 CRC 校验位保留为模块自身出厂默认值，成功实现稳定通信。

## 其他高频踩坑记录
1. **FIFO 死锁**：当发送失败（MAX_RT 触发）时，nRF 内部缓冲区极易被填满导致死锁。解决方案：在每次 `NRF_Send` 发包前，加入 `FLUSH_TX` (0xE1) 指令强制清空 FIFO。
2. **SPI 总线冲突**：nRF24L01 与 W25Q64 共用 SPI1，初始化时必须将 W25Q64 的 CS 引脚（PA4）明确拉高，防止总线抢占导致数据错乱。
3. **OLED 刷新残影**：刷新数据时，必须使用 `sprintf` 填充空格补齐长度，防止短数据无法完全覆盖旧数据。
4. **DHT22 时序被中断打断**：微秒级单总线时序极易被 SysTick 打断，读取时必须使用 `__disable_irq()` 和 `__enable_irq()` 关中断保护。

##  实测数据
- 成功实现双板单向无线收发。
- 连续发包测试：**成功 140 次，失败 14 次**（失败多为上电时间差导致的初始丢包，后续通信稳定）。

##  技术栈
- **主控**：STM32F103C8T6
- **通信**：nRF24L01 (2.4G SPI)、UART
- **存储**：W25Q64 + FAL + FlashDB (KVDB/TSDB)
- **传感器**：DHT22、ADC 光敏电阻
- **显示**：0.96寸 I2C OLED
