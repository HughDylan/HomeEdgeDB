# HomeEdgeDB 简历项目条目

**项目**: HomeEdgeDB — 基于 FlashDB 的智能家居边缘网关
**时间**: 2026.10 - 2026.11
**技术栈**: STM32F103C8T6 / FlashDB + FAL / W25Q64 (SPI Flash) / I2C OLED / DHT22 / nRF24L01+

## 项目描述

1. 基于 STM32F103C8T6 + W25Q64(8MB SPI Flash) 搭建边缘网关存储方案，移植 FlashDB 与 FAL 存储抽象层，按扇区边界划分 KVDB(512KB) 与 TSDB(7.5MB) 双分区：KVDB 存阈值配置，TSDB 存带时间戳的传感器记录。

2. 手写 W25Q64 SPI 驱动(读 JEDEC ID 0xEF4017 验证通信)，实现传感器数据每 10 秒自动追加入库；实测断电重启后记录条数接续、KVDB 配置项跨重启保持，验证了掉电不丢数据的存储可靠性。

3. 实现 DHT22 单总线驱动，解决微秒级时序被中断打断的问题：读取期间关闭总中断保护采样窗口，在 DATA 线增加 10kΩ 外部上拉改善上升沿，并将采样点标定为 30μs，使校验失败率降为 0。

4. 编写 nRF24L01+ 无线驱动，两块 STM32 节点板实现传感器数据帧单向传输；与 W25Q64 共用 SPI1，通过片选互斥与 CS 强制拉高解决 MISO 总线争用；自定义 32 字节 payload 承载 ASCII 协议帧，配置频道 76 / 1Mbps / 2 字节 CRC；近距离实测收包成功率约 90%(成功 140 帧 / 失败 14 帧)。

## 面试可展开的三个技术点

- **存储选型**: 为什么用 FlashDB 而不是裸写 Flash(磨损均衡、掉电原子性、查询接口)
- **时序敏感外设**: DHT22 为什么要关中断、为什么 30μs 采样
- **无线故障定位**: 两端寄存器全部正常但零收包 -> CRC 位数不一致导致静默丢包
